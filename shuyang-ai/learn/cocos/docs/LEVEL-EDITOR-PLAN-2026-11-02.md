## 〇、Silas 五问 · 调研答复（附来源）

### 1）怎么制作一个关卡编辑器？

**做法**：做一个与**玩家视角尽量一致**的所见即所得（WYSIWYG）编辑视图，并保证**编辑器内一键试玩**的短循环——改完立刻跑，跑完立刻回改。  
设计工具应服务「设计意图」，而不是堆功能（Richard Rouse III, *Designing Design Tools*, Game Developer）：  
https://www.gamedeveloper.com/design/designing-design-tools

**工程底线**（浏览器关卡编辑器通识 + 本仓现状）：

1. **一份可序列化、带版本号的关卡文档**，编辑器与运行时**共用**（本仓已有 `xygo-custom-level` v1.2）。  
2. **实体种类**清晰（起点 / 陷阱 / 奖励 / 终点…），命令可撤销（以后加）。  
3. **快循环**：palette → 摆放 → playtest → 回编辑。

参考模式：SpriteShip / picogame / Tilemap.dev 一类「调色板 + 网格吸附 + 放置/选择/擦除 + 层 + 撤销 + 自动存 + 出生点试玩」。

### 2）关卡编辑器要达到哪些效果？

| 效果 | 孩子能感到什么 | 本仓对应 |
| --- | --- | --- |
| **看得见** | 摆的和玩的差不多 | 工坊画布 ≈ custom-play 跑道语义 |
| **立刻试** | 改完马上跑 | 工坊「去玩」→ `custom-play` |
| **存得住** | 下次还能打开自己的关 | 扩展本地「我的关」名册（与正式 1–8 隔离） |
| **可讲故事** | 用零件排出「过关小故事」 | 起点→挡/钓→终点 |
| **可迭代** | 过不去就改，不重做整关 | 快回编辑；日后撤销 |

### 3）关卡编辑器应该有哪些维度？

**MVP（明天课 / 确认后优先做）**

| 维度 | 内容 |
| --- | --- |
| 视图 | 编辑视图 ≈ 玩家横屏视角 |
| 零件 | 起点 · 挡人(陷阱) · 钓人(金币/箱) · 终点 |
| 操作 | 放置 / 擦除；前两格安全 |
| 循环 | 试玩 ↔ 回编辑 |
| 存档 | 单槽「我的第 1 关」+ version 字段 |
| 入口 | 选关「我的关」/ 第9 绿卡不与 Boss 1–8 混名 |

**Later（加深课）**

| 维度 | 内容 |
| --- | --- |
| 层 | 地形层 / 物件层 / 触发层 |
| 命令 | 撤销·重做；多选；网格吸附开关 |
| 名册 | 多关 roster（我的第 N 关）· 导出名 · 复制关 |
| 校验 | 无起点/无终点警告；难度粗检 |
| 钩子面板 | 「惊喜点 / 节奏点」自检清单（非强制） |
| 联机 | 可选：分享房间玩「我的关」（PeerJS 已有，不当明天范围） |

### 4）关卡编辑器怎么实现关卡的设计？

**设计 = 用受限零件组合出可通关体验**，不是自由画图：

1. **教-测-扭（teach–test–twist）节奏**：先安全教会走，再测反应，最后加一个小转折（多一枚藏币或错位陷阱）。  
2. **挑战 ≈ 技能（心流）**：明天只要求「能跑通 + 有一点刺激」，不追求难。  
3. **文档驱动**：编辑器写入 JSON → 运行时只读同 schema；禁止编辑器私有格式。  
4. **本仓路径**：`visual-workbench` 当编辑壳；`custom-play` 当运行时；扩展 `xygo-custom-level`（保持 v1.2 兼容，增量字段）；「我的关」名册键与正式进度 `sycocos-level-progress` 分开。

### 5）怎么让玩家进入这个钩子（engagement hook）？

结合 Guul Games 类游戏心理、CHI PLAY 好奇模式，以及成长屋已教的 **上钩 vs 自己决定停**：

| 钩子 | 在「我的关」里怎么用 | 孩子侧觉察 |
| --- | --- | --- |
| 变化奖励 | 金币/箱不要排成一条直线 | 「有没有一个惊喜？」 |
| 心流 | 陷阱密度适中，留路 | 「太难/太易就改」 |
| 教-测-扭 | 前段安全 → 中段测 → 末段小转折 | 「故事有开头和结尾吗？」 |
| 好奇缝隙 | 半遮的币、拐角后的刺 | 「我想看看后面是什么」 |
| 张弛 | 危险段后给一格喘息 | 「喘口气再冲」 |
| **停点** | 开玩前勾「通一关/玩 N 分钟就停」 | **上钩能造，停点自己定** |

明天课只做第九步「一分钟钩子自检」，不重开「入迷」长课。

## 二、实现路径（技术选型）

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 引擎 | **不新开**；继续 Cocos2d-JS Lite | 孩子已熟；Pages 已跑通 |
| 编辑壳 | `visual-workbench.html`（+ `workbench` 同源数据） | 已有摆关/设置/试玩出口 |
| 运行时 | `custom-play.html`（当前 tip 如 c51） | 已读 `xygo-custom-level` |
| 文档格式 | 延续 **v1.2** JSON；仅**加字段**不破旧档 | 编辑器↔运行时同一份 |
| 我的关 | **独立名册**（勿写入正式 1–8 Boss 表） | 产品铁律：自定义 ≠ 正式关 |
| 选关 | `level-select` 第9 /「玩第9关·我的关卡」已指向 custom-play | 加深时把名册挂到此入口 |
| 联机 | PeerJS **保持**；不当明天 MVP | 课题 B 另课 |
| 存档介质 | `localStorage` 先 | 无后端；手机可硬刷验证 |

**建议 schema 延伸（确认后实现时再落代码）**：

```text
xygo-custom-level (v1.2+)  — 当前编辑/试玩槽
xygo-my-levels             — { version, levels:[{ id, title, savedAt, doc }] }
sycocos-level-progress     — 正式 1–8 进度（不动）
```
