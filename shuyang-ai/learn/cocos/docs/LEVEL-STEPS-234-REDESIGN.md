## 1. 调研摘要（成熟横版 / 平台跳跃）

### 1.1 核心课：关卡自己教，不靠长文

成熟 2D 平台跳跃把「一关」当成一课：用地形、危险、奖励的摆法教玩家，而不是弹教程墙。经典四拍（Kishōtenketsu / Hayashida · *Super Mario 3D World*）：

1. **Introduce（安全认识）** — 新机制单独出现，失败成本低  
2. **Develop（加难练习）** — 同机制更难用法  
3. **Twist（意外拧一下）** — 机制与别的东西组合  
4. **Conclude（短考收束）** — 考完就换新想法，避免磨到腻  

参考：[Pathwise · Levels that teach](https://pathwisehq.com/learn/game-design/05-level-design)；[Simon Sanchez · Teaching the Player](https://www.simonsanchez.art/articles/teaching-the-player)。

### 1.2 组件五类（Smith 等 · 2D Platformer 分析框架）

| 组件 | 含义 | 我们课上的对应 |
| --- | --- | --- |
| **Platforms 几何** | 可站可行的表面、断坑、坡 | 格子地面、断坑、**凹槽**、台阶高度 |
| **Obstacles 障碍/伤害** | 会伤人或打断节奏的东西（含坑） | **陷阱六类** + 坑 |
| **Movement aids 移动辅助** | 弹簧、绳、加速环等 | **弹跳台阶 / 弹簧**、凹槽借力 |
| **Collectibles 收集物** | 币、道具、武器、引导面包屑 | **小金币 / 大金币 / 宝箱**；现有地图币 |
| **Triggers 触发器** | 改关卡状态的开关等 | 频率冒刺节拍；单关设置里的参数（草案） |

参考：[Smith et al., A Framework for Analysis of 2D Platformer Levels (PDF)](https://eis.ucsc.edu/papers/smith-sandbox-08.pdf)；[Launchpad / rhythm groups (PDF)](https://users.soe.ucsc.edu/~ejw/papers/Smith-Launchpad-TCIAIG-2011.pdf)。

### 1.3 节奏、风险回报、可读威胁

| 维度 | 成熟做法（摘要） | 引文 |
| --- | --- | --- |
| **Pacing / 安全点** | 张→弛交替；安全落脚点控制「关卡感觉」；长关 = 高赌注 | Celeste GDC/Workshop：[Designing Celeste](https://gameindustrylibrary.com/documents/level-design-workshop-designing-celeste)；[MindForge teaching rooms](https://mind-forge.org/lesson/gd-19-teaching-through-design) |
| **Risk / Reward** | 安全低奖路径 vs 高技高奖分支 | [Level Design Patterns in 2D Games (IEEE CoG 2019 PDF)](https://ieee-cog.org/2019/papers/paper_124.pdf) |
| **Telegraphing** | 威胁先给可读预兆（闪光/起手/预警格），反应窗 ≥ 人类反应底 | [Hayao · Telegraphs](https://hayao.dev/docs/codex/system-telegraphs) |
| **Safe first meet** | 新敌人/陷阱第一次出现在平地、低代价处 | Pathwise 同上；Mario 1-1 Goomba |
| **Breadcrumbs** | 用币/光引导路线，少用文字箭头 | Pathwise |
| **Enemy / tool layering** | 几何定稿后再摆敌；能力当「钥匙」改变旧区读法 | Hollow Knight 敌层：[Jason de Heras](https://www.jasondeheras.com/gamedesign/2023/12/22/enemy-design-layers-in-hollow-knight)；Metroidvania 回访原则 |

### 1.4 对本课（孩子 · 手机横屏 · Cocos）的直接含义

- **一屏一事**：844×390 不能堆控件墙；筹码短、可横滑；单关设置用折叠/页内分段，不新开顶栏课。  
- **教→练→变→考** 已在 `tonight-waves-v1` 四波出现——与 Kishōtenketsu 同族，应保留语义，扩展元素时仍按波摆。  
- **前两格安全** = 「Safe first meet / Introduce」的课内硬合同。  
- **频率（②）** = 显式教「节拍 / 可读威胁」——地刺冒起间隔就是 telegraph + pacing 旋钮。  
- **摆关（③）** = 孩子当关卡设计师：组件五类进调色板。  
- **装备（④）** = 武器 = 对陷阱属性的**回答方式**（克制 / 无效 / 有代价），不是把商店塞回摆关。

## 2. 关卡设计维度表（taxonomy）→ ②③④职责

| 维度 | 孩子要懂的一句话 | 主要落在 | 控件 / 数据（提案） |
| --- | --- | --- | --- |
| 几何 · 地面 / 断坑 | 「路怎么断、怎么接」 | ③摆放 | 地面格、擦、断坑标记 |
| 几何 · **台阶 / 弹跳** | 「帮你跳得更高更远」 | ③摆放 | 弹跳台阶 / 弹簧（现「弹」） |
| 几何 · **凹槽** | 「卡一下或借力翻过去」 | ③摆放 | 凹槽道具（**新增草案**） |
| 危险 · **陷阱六类** | 「每一种伤法不一样」 | ③摆放 + 单关设置属性 | 火/刺/烟雾/电/掉石头/沼泽 |
| 节奏 · **频率** | 「多久冒一次 / 多久伤一次」 | **②** 主教；③可继承默认 | 真滑条 1–5s；单关可覆盖（待批） |
| 奖励 · **三档金币** | 「小奖喘气、大奖冒险、宝箱高风险」 | ③摆放 | 小金币 / 大金币 / 宝箱（数值 TBD） |
| 角色 | 「绿红蓝忍者是谁在跑」 | 跨步展示；试玩选角不变 | 三忍者；本方案不改选角栈 |
| 武器 | 「买了才能装；不同武器对陷阱反应不同」 | **④** | 飞镖15 / 砍刀35 / 枪60（改价须写清） |
| 反馈 / 预兆 | 「危险要看得见」 | ②跑一次 + 试玩表现 | 冒刺前摇、火光、烟雾紫雾等（实现刀） |
| 难度曲线 | 「先易后难、中间喘气」 | ③检查条 + 默认四波 | 开头空、先易后难、喘气、花样≤3 |
| 联网 | 「联机是可选项」 | L3；**本方案不扩** | PeerJS 保持 |

**映射一句话**：②教「时间维度的钩」；③教「空间里摆钩与奖」；④教「用装备回答钩」——三步分工，不合并。

## 3. ②频率 · 重设（孩子做什么 / 控件 / 信息架构）

### 3.1 孩子带走什么

- 「地刺不是一直扎——它有**节拍**。」  
- 「调快 = 更密的钩；调慢 = 更好躲，但可能憋一口气。」  
- 「**跑一次**亲眼看节拍，再回答：哪一点在钓你。」（对齐①的「看见钩子」）

### 3.2 信息架构（横屏）

```
┌──────── 顶栏 ①…⑥（② 当前绿）────────┐
│ 画布：跑道 + 地刺按间隔冒起预览          │
│ 画布外：标题「② 频率」+ 小宇一句旁白     │
├──────────────────────────────────────┤
│ [−] 滑条 1–––●–––5 秒 [+]   [跑一次]   │
│ 旁白位：「现在每隔 X 秒冒一次」          │
└──────────────────────────────────────┘
```

- **必有**：真滑条约 **1–5s**、加减、「跑一次」。  
- **不把**整页改成多陷阱属性编辑器（那是③的「单关设置」）。  
- 可选增强（待批）：跑完弹一句选择「太密 / 刚好 / 太疏」——仍属②，不新开步。

### 3.3 与现网 / 验收

| 项 | 现网 | 本方案 |
| --- | --- | --- |
| P-L2-3 / B7 | 滑条 + 跑一次 | **保留**；文案可强调「节拍=钩」 |
| 与③关系 | 频率影响地刺 | ②调的是**全局课内默认节拍**；③单关可覆盖「本关刺间隔」（待批，默认继承②） |
| 与①关系 | 弱 | 跑完可回声①「看见钩子」短句（不改①代码直至①拍板） |

### 3.4 验收要点（提案）

- 能把滑条从 1 拖到 5 并看到间隔变化。  
- 点「跑一次」动画/预览按当前秒数冒刺。  
- 横屏拇指可点「跑一次」（≥约 44px）。  
- 人名仅伍澍暘 / 小宇。

## 4. ③摆关 · 重设（调色板 / 属性 / UI）

### 4.1 孩子带走什么

- 「我是关卡小设计师：摆**道具、陷阱、奖励**。」  
- 「前两格是家——危险不能放门口。」  
- 「每种陷阱**属性不同**；金币有小/大/宝箱三档。」

### 4.2 UI 硬结构：一列「设计关卡」两段

**不要**做成两个顶栏入口。同一 ③ 场景内：

```
③ 摆关
└─ 设计关卡（一列）
   ├─ A. 摆放关卡     ← 调色板筹码 + 格子画布（主操作面）
   └─ B. 每个关卡的设置 ← 页内分段 / 抽屉 / 折叠（同列下方或侧内嵌）
```

| 段 | 孩子做什么 | 内容 |
| --- | --- | --- |
| **A 摆放关卡** | 选筹码 → 点格子放下 / 擦掉 | 道具、陷阱、奖励、擦 |
| **B 每个关卡的设置** | 调「这一关」参数 | 关卡名（可选）、默认继承的刺间隔、本关启用陷阱子集、奖励密度、检查条结果只读 |

切换方式提案（待批选一）：同列 **分段标题可点展开**；或底栏「摆放 | 设置」二段切换——**仍在③内**，不新增⑥以外顶栏步。

## 5. ④装备 · 重设（武器 × 陷阱 × 经济）

### 5.1 孩子带走什么

- 「钱不够就买不了——先赚再买。」  
- 「先**买**再**装备**；没装备仍是手里剑。」  
- 「不同武器对陷阱**不一定有用**——有的只能躲。」（为属性表互动埋线）

### 5.2 为何④不吞回③

| | ③摆关 | ④装备 |
| --- | --- | --- |
| 角色 | 关卡设计师 | 冒险者采购 |
| 主操作 | 放格子 | 看钱包、买、装 |
| 失败反馈 | 检查条 / 禁放闪红 | 「钱不够」禁用 |

③ 可有文案按钮「去④买武器」——**跳顶栏④**，不把商店 UI 嵌回摆放列（避免④被吞）。

### 5.3 商店规则（现网合同 · 改价须写清）

| id | 名 | 价格 | 试玩行为（现） | 改价？ |
| --- | --- | --- | --- | --- |
| dart | 飞镖 | **15** | 三发各 1 伤 | 保持，除非 Silas 批新价 |
| blade | 砍刀 | **35** | 身前一刀 2 伤 | 同上 |
| gun | 枪 | **60** | 一发 4 伤、间隔长 | 同上 |

- 默认练习金 **100**（够买枪还余）；`coins===0` 且无武器时补发一次。  
- 钱不够：**买不了**（按钮禁用或诚实提示）。  
- 已买再点 = **装备**。  
- 存档 `wallet` v1.2；本方案**不改**键名。  
- 若 Silas 要改价：必须在本表改数字 + 同步 PRODUCT P-L2-5 / B16 / DESIGN 钱包表后才许动代码。

|  | 火 | 刺 | 烟雾 | 电 | 掉石头 | 沼泽 |
